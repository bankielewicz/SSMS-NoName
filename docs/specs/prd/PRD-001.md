# PRD-001 — NoName MVP: single-instance SSMS 22 DBA tools around a redacted AI prompt builder

## 1. Summary

NoName (a working slug; the product name is open) is an SSMS 22 extension suite for a DBA working on one SQL Server instance. It reads the instance's own data (DMVs, Query Store, the error log and system_health) in one light tool window, and turns any query, error, plan, deadlock or row into an AI prompt that is built locally and redacted before the user copies it into whatever AI chat their organization allows. The MVP (version 0.1.0) is a public open-source release; everything else that BRN-001 promoted is written here as a fully specified backlog with its preconditions.

## 2. Problem and opportunity

Many organizations don't let AI tools connect to their databases, and many turn off SSMS's own Copilot route or never install it (BRN-001#PRB-03). A DBA who wants AI help then pastes SQL Server work into an approved chat and must first delete logins, server names and secrets by hand (BRN-001#PRB-01). Values buried in execution plans and deadlock XML slip through that hand pass (BRN-001#PRB-02), neither the DBA nor a security reviewer can see or prove exactly what left the machine (BRN-001#PRB-04), sensitivity differs by person and organization (BRN-001#PRB-06), and writing a good prompt by hand takes time and gives uneven answers (BRN-001#PRB-07).

The same DBA works on one instance at a time from SSMS, while the tools on offer look like enterprise monitoring platforms for many servers (BRN-001#PRB-30), and a dashboard full of links and heavy panels makes SSMS lag on a workstation (BRN-001#PRB-31). Query Store's regressions and plan changes sit in separate report windows (BRN-001#PRB-32), the error log and system_health deadlocks need separate viewers and hand-written queries (BRN-001#PRB-33), what was seen is gone when SSMS closes (BRN-001#PRB-34), and newer SQL Server capabilities stay invisible unless the DBA knows where to look (BRN-001#PRB-35). There is no single view of one instance's health (BRN-001#PRB-28), and during an incident the last few seconds of waits, the blocking tree and replica state are not in one place (BRN-001#PRB-17).

Around that core sit daily DBA chores that the backlog addresses: unconfirmed apply-mode script runs (BRN-001#PRB-11), hand-filled placeholders (BRN-001#PRB-12), PRINT capture limits (BRN-001#PRB-14), Extended Events captures left running (BRN-001#PRB-18), fixed index-maintenance thresholds (BRN-001#PRB-19), unchecked T-SQL conventions (BRN-001#PRB-20), references that can't be found before a migration (BRN-001#PRB-21), unreadable encrypted modules (BRN-001#PRB-22), Agent jobs not visible on one time axis (BRN-001#PRB-23), job changes that need a DBA or near-sysadmin rights (BRN-001#PRB-24), long scripts with disruptive sections (BRN-001#PRB-25), unversioned server objects (BRN-001#PRB-26) and actions nobody can later prove (BRN-001#PRB-27).

For the maintainer, every SSMS update can silently break the undocumented SSMS APIs an extension relies on (BRN-001#PRB-09), and the diagnostic extension's clicks give no visible feedback today (BRN-001#PRB-10).

## 3. Users and personas

| Persona | Goal | Context and frequency |
|---|---|---|
| Bryan, the owner and first user (DBA and developer) | AI help with a query, plan, error or deadlock at work, and a single-instance view of health | Daily, in SSMS 22, where AI may not connect to databases |
| Open-source adopters (proposed, not observed): senior DBAs, BI developers, system engineers, database engineers and database managers | The same jobs in their own organizations, with their own sensitivity rules | After the public 0.1.0 release |
| DBA in an incident or a change window | Live waits, blocking, Query Store, the error log and deadlocks for one instance; later, safe change-script runs | During incidents and change windows |
| Security and compliance reviewers (affected, not users) | Decide whether the tool is acceptable at work | When a team adopts it; they see receipts, logs and the guarantees in section 7 |
| The maintainer (Bryan, later contributors) | Keep the extension working across frequent SSMS updates | After each SSMS update |
| Job operator in an AD group, not sysadmin (backlog) | Start, stop or re-time specific Agent jobs | After the MVP, through FR-026 and FR-027 |

The multi-server estate DBA is out of scope: BRN-001 version 2 puts a single instance first. Users whose organizations allow Copilot with MCP are served by Copilot today. SSMS runs only on Windows, so macOS and Linux desktop users are excluded by the host.

## 4. Goals and non-goals

**Goals**
- A DBA gets an AI prompt for a query, an error, a plan, a deadlock or a row without redacting by hand: no secret ever leaves the machine in a prompt, and no identity does unless the user turned that redaction off in the preview.
- The user and a security reviewer can see exactly what leaves (the preview and the receipt) and what the tool guarantees.
- One light tool window per instance shows live waits and blocking, Query Store, the error log, deadlocks and health facts, without making SSMS lag.
- Every core feature works with or without SSMS's AI component, and a diagnostic rerun after each SSMS update shows a break before a user meets it.
- The backlog after the MVP is specified as exactly as the MVP, with every item's source and preconditions recorded.

**Non-goals** (explicitly out of scope)
- Monitoring many servers from one view, or a central repository for an estate (parked in the brainstorm: single instance first).
- Sending prompts to an AI service: the user copies them (NFR-004).
- An MCP channel (parked in the brainstorm until the engine exists).
- An administrator-managed redaction policy: settings are per user (NFR-005).
- A clipboard or browser redactor instead of the extension (rejected in the brainstorm: it can't read the connection).
- Supporting SSMS 21 or earlier.

## 9. Constraints and dependencies

- **Host.** SSMS 22 supports no third-party extensions and releases often (IDEA-NN-001 C-01, C-02). The SSMS internal APIs the extension needs are undocumented and change between updates (22.6 changed the brokered methods' signatures), which is why NFR-014, NFR-044 and NFR-045 exist and why NoName Diagnostics (FR-004, FR-008) is kept as a canary.
- **Probes.** Every class B requirement depends on a named probe passing in NoName Diagnostics; section 10 lists each as an assumption, and section 6's notes name them. Only the VSIX load and its commands (ASM-02) are proven today.
- **Server-side pieces.** The audit objects (FR-032), the history database and its Agent jobs (FR-036), and the job-delegation objects (FR-027) are NoName's own server-side components, separate from the in-process extension and all in the backlog. Every extension feature says what still works without them.
- **Third-party procedures** are prerequisites the user installs (NFR-040).
- **Owner inputs.** IDEA-NN-001's constraints C-01 to C-08 and owner inputs INPUT-NN-003 to INPUT-NN-022 are the sources of section 7's user-stated requirements.
- **Development instance.** The local SQL Server instance is the development and test server (BRN-001 section 7).

## 11. Release and rollout

- **The MVP ships as 0.1.0**, using semantic versioning, the same scheme as the diagnostic VSIX. It is a public open-source release, installed per user into SSMS 22 with SSMS's own VSIXInstaller.
- **In the MVP:** every active requirement with `release: current`. That is the prompt builder (FR-001 to FR-003, FR-005 to FR-007, FR-009), the diagnostics canary and its window (FR-004, FR-008), and the instance window (FR-013, FR-034, FR-035, FR-038, FR-040 to FR-042, FR-044, FR-048, FR-049, FR-058 to FR-061). The section 7 requirements with `release: current` also apply.
- **Launch criteria** (Bryan's rewrite, 2026-11-02):
  - Every must requirement is met, and the probe of every class B must requirement has passed on both installs (SSMS 22 with and without the AI component, in NoName Diagnostics; NFR-006, SM-05). The table below lists each class B must requirement and its gate.
  - A should requirement whose probe fails moves to later, each on its own: FR-042 if PRB-LIVE-06 fails, FR-058 (the deadlock graph) if PRB-XE-06 fails, and FR-059 if either fails.
  - PRB-UI-03 gates only the flow map; FR-034 is met by the static Overview (INPUT-NN-015).

  - The default thresholds are set from the first real instances (NFR-043).
  - The licence is chosen (section 12).
