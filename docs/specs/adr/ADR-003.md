# ADR-003 — Copy the window's connection settings and verify the extension's own connection reached the window's server and replica

## Context and problem statement

ARCH-001#DEC-03 asks how the extension's own connection is shown to reach the same server and replica as the query window when the window connects through an availability-group listener, an alias or read-only intent. PRD-001 v2 raises it as a NEEDS ADR marker affecting FR-006, FR-013, FR-034, FR-035, FR-038, FR-040, FR-042, FR-044, FR-045, FR-048, FR-049, FR-051, FR-058 and FR-059.

The extension can't run a query on the user's connection. It opens its own, with Windows authentication only (NFR-046), copying the settings PRB-SQL-01 reads from the window: server, database, application intent, multi-subnet failover, encryption, trust certificate and port (RES-NN-001 0.2.3, PRB-SQL-03). No probe reads the window's session ID (SPID) today.

## Decision drivers

- Every instance-window tab and FR-006's lookups must describe the server the user is looking at, not another replica.
- PRD-001#NFR-015: a problem shows a stated state on the panel instead of an error dialog.
- PRD-001#NFR-045: a disabled feature says why and names its probe.
- Read-only routing doesn't guarantee that two connections with the same settings land on the same secondary.

## Considered options

1. Copy the settings, then verify that the own connection reached the window's server and replica.
2. Copy the settings only, and trust them.

## Decision outcome

**Chosen option:** option 1, with verification mandatory. Bryan Ankielewicz decided this on 2026-11-06. The decision text he pasted and confirmed names a gap in the option as first written: comparing server name and replica role "with the window's" assumes the extension can learn which replica the window landed on, and it cannot run a query on the user's connection. It says:

> Verification is mandatory, not a nicety: read-only routing has been round-robin since SQL Server 2016, so identical settings do not guarantee the same secondary. Extend PRB-SQL-01 to read the window's SPID (SSMS shows it in the status bar; SMO's ServerConnection exposes ProcessID). The check is then: on the extension's own connection, look that SPID up in sys.dm_exec_sessions and match login_name and program_name. Found means same replica; absent means a different one. Fall back to comparing SERVERPROPERTY('ServerName') plus the replica role from sys.dm_hadr_availability_replica_states when the SPID is unavailable. Re-verify after every reconnect, and show the verified or mismatched state on the window's connection chip.

### Consequences

- Good: a listener or read-only intent that routes the own connection to another replica is caught, and the window shows "mismatched" instead of reading the wrong server.
- Good: the check uses only DMVs that VIEW SERVER STATE covers (NFR-009).
- Bad: RES-NN-001 must extend PRB-SQL-01 to read the window's SPID. That is a change to RES-NN-001, outside this ADR. Until the extended probe passes, only the fallback comparison is proven.
- Bad: the fallback can't tell two secondaries of the same availability group apart when both report the same role. The chip shows the fallback's result as "not verified by session" rather than "verified".
- Bad: every reconnect costs one extra lookup.

### Confirmation

- RES-NN-001's next version extends PRB-SQL-01 to read the window's SPID, and PRB-SQL-03 then logs whether the lookup found it.
- The first epic that opens the extension's own connection specifies the check, the fallback, re-verification after reconnect and the chip's states, and unit-tests the decision logic in Core under the 95% gate.
- A diagnostic run on an availability-group listener with read-only intent shows the verified and mismatched states. Until an instance in an availability group is available (FR-059's condition), only the single-instance path is checked.

## Pros and cons of the options

### Copy the settings, then verify
- Good, because a wrong replica is detected and stated, never read silently.
- Bad, because it needs PRB-SQL-01 extended and a fallback for when the SPID can't be read.

### Copy the settings only
- Good, because it is simpler and needs no new probe step.
- Bad, because read-only routing can send the own connection to a different secondary, and every tab would then show the wrong server without saying so.
